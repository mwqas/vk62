# Finding Donors for CharityML

The required submission files are `finding_donors.ipynb` (executed) and `report.html`.
The HTML includes tables, answers, code, and embedded plot images. The main task predicts
income above $50,000; it does not predict observed donations.

## Reproduce

Tested with Python 3.12.14. Create and activate an isolated Python environment, then run
these commands from this folder:

```sh
python -m pip install -r requirements.txt
python -m ipykernel install --sys-prefix --name python3
python -m jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=1800 finding_donors.ipynb
python -m jupyter nbconvert --to html --output report.html finding_donors.ipynb
```

The notebook is self-contained and needs only the included data and `visuals.py`.
Questions and result tables describe the saved executed run. Fixed seeds reproduce
model scores on the pinned software; elapsed times vary, so narrative timings refer to
the delivered run. A different environment can also change scores.

## Included supporting files

- `census.csv`: original labeled starter data.
- `visuals.py`: original Udacity visualization helper, unmodified.
- `test_census.csv`, `example_submission.csv`: optional competition inputs from the starter.
- `kaggle_submission.csv`: locally generated income predictions; not uploaded or scored.
- `analysis_metrics.json`: numerical results generated by the notebook.
- `requirements.txt`: core execution dependencies.
- `environment-lock.txt`: exact installed versions for the delivered execution.

## Evaluation choices

F0.5 is used for model selection and tuning, as the notebook requires. F1 is also reported
because the supplied rubric requests it. There is an 80/20 stratified train/test split.
Preprocessing is fitted on training rows and refitted inside cross-validation folds.
Model-family selection uses training-only CV. Holdout results are presented for the
assignment comparisons; an additional external test set would strengthen validation.

## Reviewer-requested preprocessing correction

The assignment preprocessing cell now preserves all 103 one-hot encoded columns in
`features_final` and asserts that exact count. It no longer reindexes that matrix to the
training-only schema. Model inputs are generated separately by `CensusPreprocessor`,
which learns 102 columns from this training split; one rare category occurs only in the
holdout. Each cross-validation fold still fits preprocessing independently. The notebook
explains this distinction and prints the category absent from training. All cells were
rerun after the correction, and the HTML report and ZIP were regenerated.

The notebook ends with a criterion-by-criterion self-assessment and limitations. Review
the results and explanations before submitting; reviewer acceptance cannot be guaranteed.
